# ERP + CRM Operations Portal — Backend

Node.js + TypeScript + Express + Prisma + PostgreSQL.

## Setup

1. Install dependencies:
   ```
   npm install
   ```
2. Copy the env template and fill in your own values:
   ```
   cp .env.example .env
   ```
   - `DATABASE_URL`: your Postgres connection string (local, Render, Supabase, or Neon)
   - `JWT_SECRET`: any long random string
   - `CORS_ORIGIN`: your frontend URL (defaults to `http://localhost:5173` for local Vite dev)
3. Generate the Prisma client and run migrations:
   ```
   npx prisma generate
   npx prisma migrate dev --name init
   ```
4. Seed 4 test users (one per role, password `password123` for all):
   ```
   npm run prisma:seed
   ```
5. Start the dev server:
   ```
   npm run dev
   ```
   API runs at `http://localhost:4000`.

## Environment variables

Managed via `.env` (never committed — see `.gitignore`). `.env.example` documents every
variable required. In production (Render), set these as dashboard environment variables
instead of a committed file.

## Deployment (Render)

1. Push this repo to GitHub.
2. Create a new **PostgreSQL** instance on Render, copy its internal connection string.
3. Create a new **Web Service** on Render pointing at this repo's `backend` folder.
   - Build command: `npm install && npx prisma generate && npm run build`
   - Start command: `npx prisma migrate deploy && npm start`
4. Set environment variables in the Render dashboard: `DATABASE_URL`, `JWT_SECRET`, `CORS_ORIGIN` (your deployed frontend URL).
5. After first deploy, run the seed script once via Render's shell: `npm run prisma:seed`.

## API overview

All protected routes require `Authorization: Bearer <token>` (obtained from `POST /auth/login`).

- `POST /auth/register`, `POST /auth/login`
- `GET/POST /customers`, `GET/PATCH /customers/:id`, `POST /customers/:id/follow-ups`
- `GET/POST /products`, `GET/PATCH /products/:id`, `POST/GET /products/:id/stock-movements`
- `GET/POST /challans`, `GET /challans/:id`, `PATCH /challans/:id/confirm`, `PATCH /challans/:id/cancel`

See the Postman collection at `postman/erp-crm.postman_collection.json` for full examples.

## Known limitations

- `POST /auth/register` is currently open (no admin gate) to make seeding test accounts for
  the assignment easier. In production this should be locked to Admin-only.
- Challan numbers are generated by counting existing rows — fine for this assignment's scale,
  but a real system with concurrent writes should use a DB sequence to avoid a race condition.
- No file/image upload (product image to S3) implemented — listed as a bonus item.
